1. 제품 개요 
 
1.1 제품명 및 목적 
제품명: WorkFlow AI 
WorkFlow AI는 사내 내부망에서 운영되는 AI 기반 업무 협업 플랫폼입니다. 팀 단위의 프로젝트와 개인 업
무를 통합 관리하고, 스톱워치 기반 실적 데이터를 축적하여 AI가 최적의 업무 담당자를 자동 추천하는 것
을 핵심 목표로 합니다. 
 
구현의도는 내부 AI 활용 확대를 통한 업무 생산성 향상입니다.  
 
1.2 배경 및 문제 정의 
• 엑셀·수기로 관리하던 업무 내역으로 인해 실적 데이터 축적이 불가하여 AI 활용 기반 부재 
• 팀장이 경험에 의존하여 수작업으로 담당자를 배정, 비효율적이고 편향 발생 가능 
• 진행 중인 프로젝트 진척도를 정량적으로 파악하기 어렵고, 다단계 검증 프로세스 반영 불가 
• 개인별 업무 부하를 실시간으로 파악하지 못해 과부하·유휴 상태가 반복됨

4. 데이터 구조 및 진척도 계산 
 
4.1 프로젝트 3 단계 구조 
모든 프로젝트는 아래 3단계 계층으로 관리됩니다. 
 
프로젝트 계층 구조 
프로젝트 (Project) 
  └── 소프로젝트 (Subproject)  ← 담당자 1명 배정 
        └── 세부 태스크 (Task)  ← 가중치 보유 (합계 = 100%) 
 
4.2 세부 태스크 가중치 (기본값) 
아래는 검증 프로세스 기준 기본 가중치입니다. 관리자가 프로젝트별로 커스터마이징 가능합니다. 
 
세부 태스크 가중치 누적 
플랜트 준비 5% 5% 
펌웨어 준비 10% 15% 
롬라이팅 15% 30% 
리프로 20% 50% 
AUD 자동화 검증 50% 100% 
 
4.3 진척도 계산 규칙 
단계 계산식 예시 
소프로젝트 진척도 완료 태스크 가중치 합산 플랜트+펌웨어 완료 → 15% 
전체 프로젝트 진척도 완전 완료 소프로젝트 수 ÷ 전체 수 
× 100 
4개 중 1개 완료 → 25% 
개인 평균 진척도 담당 소프로젝트 진척도 합 ÷ 담당 
수 
60% + 40% → 평균 50% 
※ 소프로젝트가 100% 완료(모든 태스크 완료)될 때만 전체 프로젝트 진척도에 반영됩니다.

5.2 가중치 기반 진척도 관리 
기능 개요 
각 세부 태스크에 가중치를 부여하여 단계별 진척도를 정량 계산합니다. 단순 완료/미완료가 아닌 세부 단
계별 기여도를 반영하며, 소프로젝트 → 프로젝트로 자동 집계됩니다. 
 
UI 표시 요소 
• 현재 진행 단계 강조 표시 (▶ 아이콘 + 프로젝트 컬러) 
• 완료된 단계는 취소선 + 회색 표시 
• 소프로젝트 진척도 바 (색상: 진행중 → 프로젝트 color / 완료 → #22c55e) 
• 전체 프로젝트 진척도 바 (파란 박스, "완료 N / 전체 N 개 소프로젝트" 표기) 
• 개인 캘린더 모달: 본인 담당 소프로젝트의 세부 태스크 체크 가능 
• 완료된 소프로젝트에 "완료 — 전체 반영됨" 배지 표시 
 
가중치 커스터마이징 (관리자) 
• 프로젝트별 태스크 가중치 설정 가능 (합계 = 100% 제약) 
• 소프로젝트 추가 시 기본 태스크 5 개 자동 생성 (기본 가중치 적용) 
• 소프로젝트 삭제 가능 (미완료 상태만) 
 
1 차/N 차 검증 단계 분리 
검증 단계별 진척도 구조 
1차 검증 소프로젝트: 기초검증1, 기능검증1, 기능검증2, 기능검증3 
N차 검증 소프로젝트: 추가 검증 배정 후 생성 
 
전체 통합 진척도 = 완전 완료 소프로젝트 수 ÷ 전체 소프로젝트 수 × 100 
(소프로젝트 내 모든 태스크 완료 시에만 전체에 반영)

5.3 AI 업무 배정 추천 엔진 
기능 개요 
신규 프로젝트 등록 시 AI가 팀원의 가용성과 직무 역량을 점수화하여 TOP 3 후보를 추천합니다. 관리자
는 가중치 슬라이더로 긴급도/난이도에 따라 추천 기준을 조정할 수 있습니다. 
 
최종 점수 산출 공식 
FinalScore = (w₁ × 가용성 점수) + (w₂ × 직무 수행 역량 점수) 
• w₁ (가용성 가중치): 긴급 업무일수록 높게 설정 
• w₂ (역량 가중치): 고난도 업무일수록 높게 설정 
• w₁ + w₂ = 1.0 (합계 100%) 
 
[관리자 UI] 가용성 우선 ◀━━━[슬라이더]━━━▶ 역량 우선 
 
① 가용성 (Availability) 산출 
• 기준: 개인 캘린더에 배정된 미완료 업무의 예상 소요 시간(T_expected) 합산 
• 점수화: 주간 가용 시간(40h) - 잔여 업무 합산 시간 = 빈 슬롯(Empty Slot) 
• 빈 슬롯이 클수록 높은 가용성 점수 부여 
• 업무 수 보정: 업무 개수가 많아도 총 소요 시간이 적으면 가용성 높음 (멀티태스킹 반영) 
 
② 직무 수행 역량 (Task Capability) 산출 
역량 점수 계산식 
CapabilityScore = (동일 키워드 업무 수행 횟수) × (T_std / T_avg) 
 
• 횟수 점수: 동일 키워드(예: 펌웨어 기초 검증) 수행 횟수를 로그 함수로 가중치 부여 
• 효율 점수: T_std(팀 표준 소요 시간) / T_avg(본인 평균 소요 시간) 
  → 값이 1보다 클수록 표준보다 빠른 숙련자 
 
※ Cold Start: 초기(1~2개월) 스톱워치 데이터 불충분 시 
   기존 엑셀 "인원별 주간 업무 내역"을 정규화하여 참조 
 
③ 시스템 흐름 
1. 키워드 파싱: 신규 업무 등록 시 AI(NLP)가 제어기 종류 및 검증 단계를 추출하여 검색 태그로 변환 
2. 추천 후보 생성: 계산식에 따라 TOP 3 인원을 후보 카드로 제시 
3. 배정 확정: 관리자가 후보 선택 시 즉시 개인 캘린더에 업무 등록, DB 의 Task_Queue 갱신

8. 비기능 요구사항 
 
8.1 성능 
• AI 추천 응답 시간: 1.5 초 이내 (UI 로딩 표시 기준 1.4 초) 
• 타이머 정밀도: 1 초 단위 정확도 유지 
• 캘린더 렌더링: 월 이동 및 필터 변경 시 200ms 이내 
• DB 쿼리: PostgreSQL 인덱싱 최적화로 가중치 필터링/Join 연산 100ms 이내 
 
8.2 디자인 원칙 
• 디자인 토큰 기반: 색상, 폰트, 반경을 상수로 정의하여 일관성 유지 
• 주 색상 #534AB7 (보라), 배경 #F8F8F5 (따뜻한 흰색), 카드 #FFFFFF 
• 팀원별 고유 색상 체계 (5 명 × color/bg 쌍) 
• 상태 Pill: 진행중(파랑) / 완료(초록) / 예정(회색) / 지연(빨강) 
• Inline Style 100% 적용 (CSS 모듈 미사용) 
 
8.3 보안 및 접근 제어 
• 사내 내부망 전용 — 외부 인터넷에서 접근 불가 
• 사내 계정 기반 인증 (별도 회원가입 없음) 
• 관리자/일반 직원 역할 분리 (AI 추천 실행 및 가중치 설정은 관리자 전용) 
 
8.4 확장성 
• 스톱워치 데이터 축적 후 ML 파이프라인으로 T_std(표준 소요 시간) 자동 업데이트 구조 설계 
• Cold Start 해결: 초기에는 기존 엑셀 인원별 주간 업무 내역을 정규화하여 입력 
• AI NLP 키워드 파싱 로직: 제어기 종류 및 검증 단계 자동 추출 (추후 구현) 
• 가중치 커스터마이징: 프로젝트별/유형별 세부 태스크 가중치 독립 설정
